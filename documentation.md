##Pourquoi on le fait? 

###La documentation en DevOps sert à :

* Partager les connaissances dans l’équipe et éviter la dépendance à une seule personne (réduction du Bus Factor).
* Standardiser les processus, les pratiques de développement, de déploiement et d’exploitation.
* Faciliter la collaboration entre les équipes
* Assurer la continuité des opérations
*Faciliter la maintenance du projet et permettre à un nouveau développeur de comprendre rapidement l’architecture.
*Tracer les décisions techniques et les procédures (installation, déploiement, monitoring, etc.).

*Améliorer la collaboration entre les équipes développement et opérations






##Quels outils on utilise ?

Dans un projet DevOps, plusieurs outils peuvent être utilisés pour documenter et automatiser le projet :
* Editeurs de texte
* Convertisseus 
* Plateformes en ligne
* Conflucence / Notion /
* Git : gestion de version du code et de la documentation.
* Markdown (.md) : format simple et lisible pour rédiger la documentation dans le projet.
* Docker : conteneurisation des applications pour assurer un environnement identique en développement et en production.
* Docker Compose : orchestration de plusieurs conteneurs (API, monitoring, base de données, etc.).
* Prometheus : collecte et stockage des métriques pour surveiller les applications.

Grafana : visualisation des métriques et création de tableaux de bord.




##Quels sont les standards? 

Plusieurs bonnes pratiques sont utilisées en DevOps pour maintenir une documentation claire et utile :

Documentation versionnée avec le code dans le dépôt Git.

Fichiers Markdown simples et lisibles pour faciliter la lecture par les développeurs.

Structure claire : présentation du projet, architecture, installation, déploiement, monitoring.

Instructions reproductibles : toutes les commandes nécessaires pour lancer le projet doivent être documentées.

Mise à jour régulière de la documentation lors des changements techniques.
